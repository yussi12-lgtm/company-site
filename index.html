우리가 푸는 문제

SAP는 오래 쓸수록,
코드를 아는 사람이 줄어듭니다.

buriburi는 ABAP 현장 개발자의 관점에서, 매일 마주치는 이 문제들을 풉니다.

01

문서 없이 쌓인 Z 프로그램

수년간 덧붙여진 INCLUDE와 FORM. 무엇을 하는 프로그램인지 코드를 처음부터 따라 읽어야 합니다.

02

작은 수정, 큰 영향 범위

한 줄을 고치기 위해 호출 관계와 테이블 사용처를 일일이 찾아보느라 며칠이 걸립니다.

03

알면서도 못 고치는 성능 문제

느린 걸 알지만 운영 중인 코드라 손대기 부담스럽고, 개선 효과를 설명하기도 어렵습니다.

제품

분석부터 리팩토링까지,
ABAP 개발 흐름 그대로.

코드 분석

프로그램 전체를 읽고 구조와 흐름을 한눈에 정리합니다.

  • INCLUDE · FORM · 메서드 호출 관계 시각화
  • 테이블 접근과 데이터 흐름 추적
  • 문서 없는 프로그램의 기능 요약

리팩토링

동작은 그대로 두고, 읽기 쉽고 빠른 코드로 바꿉니다.

  • LOOP 안 SELECT 등 성능 병목 개선
  • 신규 ABAP 문법과 내부 테이블 처리 최적화
  • FORM 서브루틴의 클래스 · 메서드 구조화

품질 점검

팀의 기준에 맞춰 코드를 일관되게 관리합니다.

  • 명명 규칙과 Clean ABAP 기준 점검
  • S/4HANA 전환 시 호환성 이슈 탐지
  • 변경 전후 비교로 빠른 코드 리뷰

리팩토링 예시

같은 결과, 더 적은 DB 접근.

buriburi는 바꾼 코드만 내놓지 않습니다. 왜 바꿨는지, 무엇이 달라지는지 함께 보여 줍니다.

무엇이 바뀌나반복 SELECT SINGLE을 FOR ALL ENTRIES 한 번으로 묶었습니다.
왜 바꾸나데이터가 많을수록 DB 왕복 횟수가 실행 시간을 좌우합니다.
무엇이 그대로인가gt_vbak에 채워지는 결과는 변경 전과 같습니다.

접근 방식

AI는 제안하고,
결정은 개발자가 합니다.

1

읽기

프로그램과 관련 오브젝트를 함께 읽어 전체 맥락을 파악합니다.

2

진단

성능, 구조, 규칙 위반 등 개선이 필요한 지점을 찾습니다.

3

제안

바꿀 코드와 그 근거를 변경 전후 비교로 보여 줍니다.

4

검토 · 반영

개발자가 확인하고 승인한 변경만 반영합니다.

운영 중인 코드는
신중하게 다뤄야 합니다.

  • 근거가 있는 제안모든 변경안에 이유와 영향 범위를 함께 제시합니다.
  • 개발자 승인 후 반영자동으로 덮어쓰지 않고, 사람이 확인한 변경만 적용합니다.
  • 팀의 규칙을 따르는 코드회사마다 다른 명명 규칙과 코딩 스타일에 맞춥니다.
